# 02 — White-Box Testing & Coverage (Project Week 2)

## Role & Scope
- **Owner:** Member 2 — White-Box Testing, Unit Automation & Coverage
- **Target System:** PyTodo Pro source code (`helpers.py`, selected units of `app.py`)
- **Testing Approach:** Structural (white-box) testing of selected high-risk code units using control-flow analysis, with statement, branch and condition coverage. Tests are automated in PyTest, and coverage is measured with `pytest-cov` in branch mode. Fixed `today`/`now` values are injected so date-based results are repeatable on any day.
- **Selected Units:** `compute_urgency()`, `is_valid_password()`, `is_valid_username()` and `completed_in_last_n_days()` in `helpers.py`; and `row_to_task()`, `get_category_name()`, `login_required_web`, `register_page()`, `login_page()` and `new_task()` → `index()` in `app.py`. The selection is justified in `white_box_findings.md`, Section 2.
- **Out of Scope:** Exhaustive structural testing of all of `app.py`, manual black-box functional testing (`01_Black_Box`), GUI/accessibility/compatibility (`03_Special_Testing`), REST `/api/` endpoints (`04_Web_API`), security/STRIDE & performance testing (`05_Security_Performance`), and the regression suite (`06_Automation_Regression`).

## How to Run
From the repository folder that contains `app.py` and `helpers.py`:
```bash
pip install -r requirements.txt
pip install pytest pytest-cov
pytest 02_White_Box_Coverage/test_whitebox.py -v --cov=helpers --cov=app --cov-branch --cov-report=term-missing --cov-report=html:02_White_Box_Coverage/htmlcov
```
> If PyTest cannot import `app` or `helpers`, run from the folder containing `app.py`, or set `PYTHONPATH=.` (Windows PowerShell: `$env:PYTHONPATH="."`). The suite creates its own temporary SQLite database, so it does not touch `pytodo_pro.db`.

## Technique Justification
1. **Statement Coverage:** Used as the baseline to make sure every executable line of the selected helper functions runs at least once, so that no code is left completely unexercised.
2. **Branch Coverage:** Applied to every decision in the selected units, such as `due <= today`, `delta_days <= 2`, `len(password) > 8` and `not session.get("user_id")`. Each decision was tested with both a True and a False outcome, because faults often sit in the branch that ordinary use never takes.
3. **Condition (MC/DC-style) Coverage:** Applied to compound conditions, such as `age.total_seconds() > 0 and age.days < n` and `c.isalnum() or c == "_"`. Each condition was tested so that it independently changes the result, because plain branch coverage can be met without ever testing the second condition.
4. **Boundary Values within White-Box Design:** Applied at each comparison operator found in the code, for example 7/8/9-character passwords, 2/3/20/21-character usernames, day offsets T-1 to T+3, and ages of 0 seconds, 7 days exactly and 7 days ±1 hour. This catches off-by-one errors (`>` vs `>=`) that 100% branch coverage alone does not catch.
5. **Path & Data-Flow Analysis:** Used to trace black-box defects to their root cause:
   - `due_date` is defined in `new_task()`, stored without validation, and used in `compute_urgency()` (`DEF-001`).
   - `username` is defined in `register_page()` and used in `login_page()` through `fetchone()` (`DEF-003`).
   - The missing `"Due Today"` path was identified (`DEF-002`).

  - `DEF-001` and `DEF-002`: confirmed.
  - `DEF-003`: confirmed, and its description was updated (tasks are hidden, not deleted).
